## What this delivers

- `tools/gates/allowlist/direct_dependencies.txt` — the checked-in allowlist. One sorted line per
  `<member> <section> <package>`, e.g. `app dependencies flutter`. Generated by the gate itself with
  `--write`, never hand-edited.
- `tools/gates/allowlist/transitive_edges.txt` — the edge exceptions, one line per
  `<package> <- <parent>`:
  ```
  http <- flutter_svg
  http <- printing
  url_launcher_platform_interface <- share_plus
  ```
  Empty of the first two rows until E08 and E17 add the packages; the file exists and is enforced from
  this commit.
- `tools/gates/check_dependency_allowlist.py` — reads `dart pub deps --json` (from stdin or a path),
  computes the direct set and the parent set of each watched package, diffs both against the checked-in
  files, and exits 1 with a unified diff naming every difference. `--write` regenerates the files.
- `tools/gates/testdata/deps/*.json` — six checked-in `dart pub deps --json` fixtures.
- A `dependency-allowlist` step in the `flutter` job of `.github/workflows/validate.yml`.
- `app/test/policy/dependency_allowlist_test.dart`.

## Why it is built this way

**The contract is edge-level, not package-level, and that is the whole reason this is an L.** `SPEC.md`
§5.3 records the correction: the first draft claimed "no HTTP client is linked" and **that was false** —
`printing` declares `http` for `PdfGoogleFonts`, `flutter_svg` declares it for `SvgPicture.network`, and
both are on the required stack. So the honest guarantee is not "http is absent" but "http has exactly two
parents, both named, both with a grep-banned entry point". A gate that cannot express *which parent* cannot
express the guarantee.

**Rejected: `audit_deps.py`'s `BANNED`/`ALLOW` lists on their own.** That script is the right technique and
this gate reads the same JSON, but its `ALLOW` set is keyed on a package **name**. Putting `http` in `ALLOW`
makes every parent acceptable forever, so a third edge — a new SVG package, an analytics SDK's http core —
arrives silently. `dependency-gate-and-audit.md` says as much: "An unjustified allow entry is a hole." This
gate keeps the name-level ban for everything else and adds a parent-set assertion for the two watched
packages.

**Rejected: `dart pub deps --style=compact` text.** `verification-ritual.md` step 4 names the compact
output, and it is the right thing for a human reading a tree. It does not distinguish direct from
transitive per member, its indentation encodes the graph in a way that changes between SDK releases, and
parsing it means the gate's correctness depends on formatting. `--json` publishes `kind` and
`dependencies` as data, which is what `audit_deps.py` already relies on.

**Rejected: a hand-maintained list of direct dependencies.** The epic brief rules it out and the reason is
worth stating: a hand list is written once and then diverges from `pubspec.yaml` at the first `dart pub
add`, at which point the gate is comparing two documents neither of which describes the app. The allowlist
here is *generated* from the resolved graph with `--write`; a human reviews the diff in the PR, which is
the review that was wanted all along.

**The diff runs both ways.** A dependency **removed** without regenerating the allowlist is also a failure
(test 3). `dependency-hygiene` rule 8: a package deleted from `pubspec.yaml` but still transitively
resolvable keeps compiling today and breaks on the clone that matters. If the allowlist no longer describes
the app, it is not evidence about the app.

**Dev-only edges are not failures, and this is the difference between a gate that lives and a gate that
gets switched off.** `build_runner` legitimately pulls a local HTTP server for watch mode, so `http`
appears under `dev_dependencies` in almost every Flutter repository, including this one from E05 onward.
`audit_deps.py` separates the set reachable from `dependencies:` (which ships) from the set reachable only
from `dev_dependencies:` (which does not), and this gate does the same: the parent-set assertion runs over
the shipping set only, and dev-only parents are printed as an informational block. A gate that fails on an
unavoidable dev dependency is a gate somebody deletes.

**Why the gate has to be proved against fixtures.** At E01 the app declares `flutter` and nothing else, so
`http` does not appear in the shipping set at all and the parent-set check has no live subject. A gate with
no subject reports success — the exact failure mode `CONVENTIONS.md` §7 and E01/T08 are about. So the
contract is proved against six checked-in `dart pub deps --json` fixtures that encode each case, and test 9
fails the gate outright when the allowlist file is empty. The fixtures are the evidence the gate works
before the packages that will exercise it exist.

**This replaces a step that stopped working.** `validate.yml`'s `invariants` job greps the **root**
`pubspec.yaml` for `http|dio|web_socket_channel|grpc|connectivity_plus`. After T01 the root is
`catchlaw_workspace`, which declares no dependencies at all, so that step became structurally incapable of
failing. It is kept — it still guards the root against a stray dependency — and this gate is what actually
covers `app/pubspec.yaml`. Left alone with no replacement, a green `invariants` job would have been read as
evidence for a claim it no longer touches.

## Tests first

Write `app/test/policy/dependency_allowlist_test.dart` and the six fixtures before writing the gate. Run
them. **All eleven must fail** — `tools/gates/check_dependency_allowlist.py` does not exist, so every
`Process.runSync` returns exit code 2 with "No such file". That is the correct red.

Each test drives the real script against a fixture, so a test that passes is a statement about the gate and
not about a mock.

| # | Test name | Fixture | Expect | Why this case exists |
|---|---|---|---|---|
| 1 | `Allowlist gate accepts the recorded graph` | `deps_clean.json` + the checked-in allowlist | exit 0 | The baseline. If this is red the allowlist is stale and every other result is noise |
| 2 | `Allowlist gate rejects a direct dependency absent from the allowlist` | `deps_extra_direct.json` | exit 1, names the package | The core diff: a `dart pub add` that nobody reviewed |
| 3 | `Allowlist gate rejects an allowlisted dependency missing from the graph` | `deps_missing_direct.json` | exit 1 | The diff runs both ways. An allowlist that no longer describes the app is not evidence about the app (`dependency-hygiene` rule 8) |
| 4 | `Allowlist gate rejects http as a direct dependency` | `deps_direct_http.json` | exit 1 | `SPEC.md` §14: "or any direct `http`, fails". This is the line the first draft got wrong |
| 5 | `Allowlist gate accepts http parented by exactly printing and flutter_svg` | `deps_two_http_edges.json` | exit 0 | The documented exception. If this failed, the gate would block the required stack and be deleted in E17 |
| 6 | `Allowlist gate rejects http with a third parent` | `deps_third_http_edge.json` | exit 1, names the third parent | `SPEC.md` §14's headline: "A third edge … fails". The whole reason this gate is edge-level |
| 7 | `Allowlist gate accepts http reachable only through dev_dependencies` | `deps_dev_only_http.json` | exit 0 | `build_runner` pulls a local HTTP server for watch mode. A gate that fails on it gets switched off, which is worse than no gate |
| 8 | `Allowlist gate rejects url_launcher_platform_interface with a parent other than share_plus` | `deps_bad_url_launcher_edge.json` | exit 1 | The second edge in §14, and the one that would arrive with any package that hands off to the browser |
| 9 | `Allowlist gate fails when the allowlist file is empty` | `deps_clean.json`, empty allowlist | exit 1 | A gate with nothing to compare against reports success. `CONVENTIONS.md` §7 — the failure mode that makes a gate worse than no gate |
| 10 | `Allowlist gate fails when the deps JSON cannot be parsed` | truncated JSON | exit 1, not 0 | A silent parse failure is a green build. `dart pub deps --json` is a schema this gate does not own (epic Risk 5) |

```dart
// app/test/policy/dependency_allowlist_test.dart
import 'dart:io';

import 'package:flutter_test/flutter_test.dart';

import 'repo_root.dart';

ProcessResult runGate({
  required String fixture,
  String? allowlistDir,
}) =>
    Process.runSync(
      'python3',
      <String>[
        repoFile('tools/gates/check_dependency_allowlist.py').path,
        '--deps', repoFile('tools/gates/testdata/deps/$fixture').path,
        '--allowlist-dir', allowlistDir ?? repoDir('tools/gates/allowlist').path,
      ],
      workingDirectory: repoRoot().path,
    );

void main() {
  test('Allowlist gate accepts the recorded graph', () {
    final r = runGate(fixture: 'deps_clean.json');
    expect(r.exitCode, 0, reason: '${r.stdout}\n${r.stderr}');
  });

  test('Allowlist gate rejects a direct dependency absent from the allowlist', () {
    final r = runGate(fixture: 'deps_extra_direct.json');
    expect(r.exitCode, 1);
    expect(r.stdout, contains('some_new_package'));
  });

  test('Allowlist gate rejects an allowlisted dependency missing from the graph', () {
    final r = runGate(fixture: 'deps_missing_direct.json');
    expect(r.exitCode, 1,
        reason: 'an allowlist that no longer describes the app is not evidence about it');
  });

  test('Allowlist gate rejects http as a direct dependency', () {
    final r = runGate(fixture: 'deps_direct_http.json');
    expect(r.exitCode, 1);
    expect(r.stdout, contains('http'));
  });

  test('Allowlist gate accepts http parented by exactly printing and flutter_svg', () {
    final r = runGate(fixture: 'deps_two_http_edges.json');
    expect(r.exitCode, 0, reason: '${r.stdout}\n${r.stderr}');
  });

  test('Allowlist gate rejects http with a third parent', () {
    final r = runGate(fixture: 'deps_third_http_edge.json');
    expect(r.exitCode, 1);
    expect(r.stdout, contains('some_widget_pack'),
        reason: 'SPEC.md §14: a third edge fails, and the message must name it');
  });

  test('Allowlist gate accepts http reachable only through dev_dependencies', () {
    final r = runGate(fixture: 'deps_dev_only_http.json');
    expect(r.exitCode, 0,
        reason: 'build_runner pulls a local HTTP server for watch mode; a gate that '
            'fails on that gets switched off');
  });

  test('Allowlist gate rejects url_launcher_platform_interface with a parent other than share_plus',
      () {
    final r = runGate(fixture: 'deps_bad_url_launcher_edge.json');
    expect(r.exitCode, 1);
  });

  test('Allowlist gate fails when the allowlist file is empty', () {
    final empty = Directory.systemTemp.createTempSync('catchlaw_allowlist');
    addTearDown(() => empty.deleteSync(recursive: true));
    File('${empty.path}/direct_dependencies.txt').writeAsStringSync('');
    File('${empty.path}/transitive_edges.txt').writeAsStringSync('');
    final r = runGate(fixture: 'deps_clean.json', allowlistDir: empty.path);
    expect(r.exitCode, 1,
        reason: 'a gate with nothing to compare against reports success — CONVENTIONS §7');
  });

  test('Allowlist gate fails when the deps JSON cannot be parsed', () {
    final r = runGate(fixture: 'deps_truncated.json');
    expect(r.exitCode, isNot(0),
        reason: 'a silent parse failure is a green build over an unwalked graph');
  });

  test('Allowlist file is sorted and deduplicated', () {
    final lines = repoFile('tools/gates/allowlist/direct_dependencies.txt')
        .readAsLinesSync()
        .where((l) => l.trim().isNotEmpty && !l.startsWith('#'))
        .toList();
    expect(lines, orderedEquals(<String>[...lines]..sort()));
    expect(lines.toSet(), hasLength(lines.length));
  });
}
```

## Implementation outline

1. Create the six fixtures under `tools/gates/testdata/deps/`. Each is a minimal `dart pub deps --json`
   document: a `packages` array whose entries carry `name`, `kind` (`root` / `direct` / `dev` /
   `transitive`) and `dependencies`. Keep them small — eight to twelve packages each — so a reader can see
   the case at a glance. `deps_truncated.json` is `deps_clean.json` cut mid-array.
2. Write `tools/gates/check_dependency_allowlist.py`:
   - Read the JSON from `--deps` (a path) or stdin. On any `JSONDecodeError` or a missing `packages` key,
     print the reason and exit 2. **Never** exit 0 on unparseable input.
   - Build `parents: dict[str, set[str]]` by inverting `dependencies`.
   - `ships` = the transitive closure from every `kind == "direct"` package; `dev_only` = the closure from
     `kind == "dev"` minus `ships`. This is `audit_deps.py`'s split, reused rather than reinvented.
   - Direct set = `{(member, section, name)}` for every `kind == "direct"` and `kind == "dev"` entry.
     Compare with `direct_dependencies.txt`; print a unified diff of both directions.
   - Watched packages = every left-hand side in `transitive_edges.txt`, plus `http` and
     `url_launcher_platform_interface` unconditionally so the two §14 names cannot be removed by deleting a
     line. For each, if it is in `ships`, assert `parents[pkg] ∩ ships` equals the recorded parent set
     exactly; print each unexpected and each missing parent by name.
   - If `direct_dependencies.txt` is empty or absent, exit 1 with "the allowlist is empty — this gate would
     pass over anything".
   - `--write` regenerates both files, sorted and deduplicated, each with a header comment naming
     `SPEC.md` §14 and this task.
3. Run `dart pub get` at the root, then
   `dart pub deps --json | python3 tools/gates/check_dependency_allowlist.py --write` to produce the real
   allowlist. At E01 it is `app`, `packages/rule_engine`, `packages/analysis_defaults` and
   `tools/content_builder` with their handful of entries. Review the file by eye before committing: this is
   the one moment where a human decides what the app is allowed to contain.
4. Add `transitive_edges.txt` with the three §14 lines commented out and a header explaining that
   `printing` and `flutter_svg` arrive in E17 and E08 and that the line is uncommented in the same PR that
   adds the package. Keep `url_launcher_platform_interface <- share_plus` in the same shape.
5. Wire the step into the `flutter` job, after `dart pub get`:
   ```yaml
   - name: Direct-dependency allowlist diff (SPEC §14)
     run: dart pub deps --json | python3 tools/gates/check_dependency_allowlist.py --allowlist-dir tools/gates/allowlist
   ```
6. Re-run the eleven tests. Then prove the gate once by hand against the live graph: add `http: ^1.5.0` to
   `app/pubspec.yaml`, `dart pub get`, run the step, watch it fail naming `http` as a direct dependency,
   and revert both the pubspec and the lock.

## Definition of done

`CONVENTIONS.md` §8 applies in full, plus:

- [ ] All 11 tests pass, and each failed first.
- [ ] The gate was proved once against the **live** graph, not only against fixtures: `http` added to
      `app/pubspec.yaml` turns the CI step red, and the pubspec and lock are reverted.
- [ ] `tools/gates/allowlist/direct_dependencies.txt` was produced by `--write` and reviewed line by line;
      no line was typed by hand.
- [ ] `transitive_edges.txt` carries the two `http` parents and the one
      `url_launcher_platform_interface` parent from `SPEC.md` §14, with the epic that activates each named
      in a comment.
- [ ] The gate names every offending package and every unexpected parent in its output. A failure that
      says only "allowlist mismatch" is not done.
- [ ] The `invariants` job's "No networking dependency" step is untouched, and the commit body states that
      it now guards only the workspace root.
- [ ] `check_no_network.sh app/lib` still passes — this gate covers layer 1's graph half, and that script
      covers layer 1's pubspec and analyzer halves. Neither replaces the other.
